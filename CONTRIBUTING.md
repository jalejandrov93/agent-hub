# Contributing

Thanks for taking a look. This project is a local orchestration layer for coding
agents; the notes below are the minimum needed to make a change that fits.

## Requirements

- **Node.js ≥ 20.19.** Use the same build the runtime uses: the native SQLite
  binding (`better-sqlite3`) is compiled per Node ABI, so a different major
  version will make the SQLite-backed tests fail with
  `compiled against a different Node.js version`. With fnm:

  ```bash
  export PATH="$HOME/.local/share/fnm/aliases/default/bin:$PATH"
  ```

- At least one supported agent CLI installed and authenticated if you want to
  exercise real delegation (`agy`, `opencode`, `copilot`, `codex`).

## Setup

```bash
git clone https://github.com/jalejandrov93/agent-hub.git
cd agent-hub
npm install          # also builds the dashboard workspace
npm test
```

## Before you open a pull request

Run the checks that cover what you touched:

```bash
npm test                              # unit + integration
npm run -w dashboard test             # if you touched dashboard/
npm run -w dashboard run typecheck    # if you touched dashboard/
node bench/run.mjs                    # if you touched routing, planner or dispatch
```

`AGENT_HUB_LIVE=1 npm run test:live` is opt-in and talks to real CLIs; it is not
part of the default suite.

**Tests come with the change.** A behavioral fix should arrive with a test that
was observed failing before the fix. If you cannot run the relevant check, say so
in the PR rather than implying it passed.

## Commit and PR conventions

- **Conventional Commits** (`feat:`, `fix:`, `docs:`, `test:`, `refactor:`,
  `chore:`) with an imperative subject.
- **No AI attribution.** Do not add `Co-Authored-By` or "generated by" trailers.
- One coherent work unit per commit: the behavior, its tests and its docs
  together.
- Work lands on **`dev`** through a pull request; `main` receives a release PR
  from `dev`. Keep PR descriptions honest about what was *not* verified and what
  is intentionally out of scope.

## Where things live

| Area | Path |
|---|---|
| MCP server entrypoint and tool registration | `src/index.mjs` |
| Routing and candidate scoring | `src/router.mjs`, `src/routing/` |
| Dispatch, policy and recovery | `src/dispatch.mjs`, `src/policy/` |
| Workflow engine and state machine | `src/workflow/` |
| Storage (SQLite + JSON fallback) | `src/storage/` |
| Agent adapters and profiles | `src/adapters/`, `src/providers/` |
| Dashboard (separate workspace) | `dashboard/` |
| Tests | `test/` (+ `test/live/`, `test/chaos/`) |
| Benchmarks | `bench/` |

## Reporting issues

Include the agent and model involved, the task type, and the relevant
`errorKind` if a delegation failed — those three usually identify the cause
without a reproduction. Never paste credentials or `.env` contents.
